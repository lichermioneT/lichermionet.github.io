# C语言编译与链接过程详解

## 1. 翻译环境与运行环境

翻译环境把源代码转化为可执行程序，运行环境负责装载并执行程序。完整构建通常经历：预处理 → 编译 → 汇编 → 链接。

## 2. 预处理

```bash
gcc -E main.c -o main.i
```

该阶段主要完成：

- 展开头文件；
- 替换宏；
- 条件编译；
- 删除注释；
- 处理其他以 `#` 开头的指令。

输出仍接近C代码，适合排查宏展开与头文件问题。

## 3. 编译

```bash
gcc -S main.i -o main.s
```

编译器进行词法分析、语法分析、语义分析、优化，并生成汇编代码。语法错误、类型不匹配和部分未声明符号通常在此阶段报告。

## 4. 汇编

```bash
gcc -c main.s -o main.o
```

汇编器将汇编指令转为机器代码，生成目标文件。目标文件包含代码、数据、符号表和重定位信息，但通常还不能独立运行。

日常也可直接执行：

```bash
gcc -c main.c -o main.o
```

## 5. 链接

```bash
gcc main.o add.o -o app
```

链接器将多个目标文件和库组合起来，完成符号解析和地址重定位。

```c
// add.h
int add(int x, int y);
```

```c
// add.c
int add(int x, int y) { return x + y; }
```

```c
// main.c
#include <stdio.h>
#include "add.h"

int main(void)
{
    printf("%d\n", add(2, 3));
    return 0;
}
```

## 6. 声明、定义与链接属性

声明告诉编译器名称和类型，定义真正分配存储或提供函数实现。`extern` 可以声明定义在其他翻译单元的符号；文件作用域 `static` 使名称只在当前翻译单元可见。

不要在头文件中随意定义普通全局变量，否则被多个源文件包含后容易产生重复定义。通常在头文件 `extern` 声明，在一个 `.c` 文件中定义。

## 7. 常见错误

- 编译错误：语法、类型或声明问题；
- undefined reference：有声明但缺少定义，或目标文件/库未参与链接；
- multiple definition：同一外部符号被多次定义；
- 库顺序错误：部分静态链接器按命令行从左到右解析；
- ABI不兼容：编译器、架构或选项不匹配。

## 8. 常用命令

```bash
gcc -Wall -Wextra -g main.c add.c -o app
nm main.o
objdump -d main.o
readelf -h app
```

`-g` 生成调试信息，`-Wall -Wextra` 开启常用警告。

## 9. 总结

理解构建阶段能快速判断错误来自源码、宏、目标文件还是链接配置。编译负责把单个翻译单元变为目标文件，链接负责解决跨文件符号并生成最终程序。
